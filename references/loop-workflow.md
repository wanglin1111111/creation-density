# 闭环工作流展开：六步 + 每周计分

## 六步工作流（人的时间只花两处）

```
真实问题 → 拆最小可交付件 → AI 出初稿 → 你判断/取舍/校验 → 交付 → 复盘沉淀
   ①              ②              ③               ④           ⑤         ⑥
```

| 步 | 做什么 | 人的投入 | AI 的投入 |
|---|---|---|---|
| ① 真实问题 | 找到"被具体的人/真实问题击中"的那件事 | **全部**（定义问题） | 无 |
| ② 拆最小可交付件 | 拆成一个可被他人直接使用的产物 | 定边界 | 辅助拆 |
| ③ AI 出初稿 | 代码/文案/方案初稿 | 给上下文与约束 | **主要** |
| ④ 判断/取舍/校验 | 初稿 → 可用：取舍、挑错、验收 | **全部**（验收结果） | 辅助验证 |
| ⑤ 交付 | 发出去/跑通/给到使用者 | 推动落地 | 辅助 |
| ⑥ 复盘沉淀 | 沉淀成 prompt/模板 | 提炼 | 辅助记录 |

人的时间只花在 ①（定义问题）和 ④（验收结果）两处，中间执行交给 AI。

## 最小可交付件判据

一个合格的最小可交付件满足三条：

1. **可被他人直接使用**：发出去的方案有人能读、跑通的代码有人能用、交付的文档有人能执行——不是"我的研究笔记"
2. **一个**：一次只做一个；同时做 3 个 = 3 个都停在"可以开始"
3. **本周可闭环**：拆出来的件如果两周都交不出，说明拆得太大，继续拆

## 每周计分表（唯一数字）

```markdown
# 创造密度周报 W<周号>
本周闭环（可被他人直接使用）：
- [产物1] 使用者/使用证据: ...
- [产物2] 使用者/使用证据: ...
数字: N 个
沉淀: prompt/模板 <名称> × M
未闭环的在研项（强制转任务或砍掉）:
- <项> → 转为: <本周交付物> 或 砍掉，原因: ...
```

纪律：
- **只认 N**："我在研究 AI"不计分；研究必须转成"本周交付物"才计分
- **使用证据必填**：没有他人使用/接收记录的"交付"是自嗨，不算闭环
- **在研项二选一**：每个未闭环项要么转为有交付物的任务，要么砍掉——不允许无限期挂着

## "可以开始"到"真的做成"的距离

原文核心观察：从「我可以开始」到「我真的把一件事做成」中间还有很长的距离，多数人卡在这里。卡点的三种形态：

| 卡点 | 表现 | 对策 |
|---|---|---|
| 开题成瘾 | 每个方向都"可以开始"，一个都没做完 | 每周计分只认闭环数；开题不计分 |
| 执行外包后验收缺位 | AI 初稿直接用，没做判断/取舍/校验 | 第 ④ 步不可跳过；交付物要过自己的验收 |
| 不做沉淀 | 每个项目从零开始，密度不复利 | 第 ⑥ 步强制：不沉淀 = 白跑 |
